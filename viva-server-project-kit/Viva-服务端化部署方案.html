01 / Executive decision

推荐方案：先做透明代理，再把 ASR 与 LLM 合并成托管管线

第一版不要重写火山 SAUC 协议。让 Viva 继续生成现在已经实测稳定的二进制首包、音频包和末包；你的服务器验证首包、注入长期密钥，并把每条 WebSocket message 原样转发。识别返回帧也原样回传。

阶段一：SAUC 二进制透明代理

目标：最快上线、结果与直连最大程度一致、客户端改动最少。

边界：一条客户端 WebSocket 对应一条火山 WebSocket；不合包、不重压缩、不改返回帧语义。

阶段二：/v2/realtime 托管语音管线

未来可让服务器在 ASR final 后直接调用方舟并通过新实时协议返回润色增量；这不属于当前 v1 AsyncAPI，必须先定义独立 /v2/realtime 机器契约，不能把新事件塞进 /v1/asr/stream。

02 / Code baseline

Viva 当前已经具备一条很好的低延迟客户端链路

现有代码并不是“录完再上传”，而是完整的实时流：麦克风常驻预热、400ms 环形预缓冲、16kHz/16bit/mono PCM、200ms 分包、火山 bigmodel_async 双向 WebSocket、partial 悬浮预览、definite 逐句上屏以及长会话轮转。

右⌘长按默认超过 150ms 才触发，减少误计费
音频预热常驻 Core Audio + 400ms pre-roll
PCM 分包16k / Int16 / mono / 6400B ≈ 200ms
SAUC WebSocket客户端直接携带火山 API Key 建连
partial / definite预览与可安全上屏文本分离
LLM 润色整段结束后由客户端再次请求模型

需要改变的不是音频前半段，而是“凭证与服务商调用归属”

现状代码证据托管化后的目标
火山长期 Key 在客户端Config.authHeaders() 生成 x-api-key 等握手头客户端只持有你的短期 access token；上游 Key 由服务器注入
LLM Key、Base URL、模型名都在客户端LLMPolisher 拼 URL、鉴权头和请求体客户端只提交文本与模式；模型、Prompt、预算都由服务器控制
Key 明文存入本地 JSON~/.config/viva/config.json，权限 0600 但未加密refresh token 放 macOS Keychain，access token 仅驻内存
上游错误直接由客户端分诊对 401/403、45000081、55000031 等做本地诊断网关返回稳定的产品错误码，同时保留火山 logid 供客服追踪

现有优势必须保留

  • 先启动 WebSocket，再取预缓冲并补发
  • partial 永不直接写入输入框
  • 只认帧头 final flags，不把 definite 当会话结束
  • 50/75 秒主动轮转，避免长会话被掐
  • 润色失败时退回原文，绝不丢内容

应顺手修正的隐私项

  • 首包当前使用本机主机名作为 user.uid；托管客户端应改为生成不可逆伪设备 ID，Gateway 只校验并默认原样转发。
  • 最近 3 条识别历史与热词会随首包发送，应在隐私说明中明确。
  • 前台 App 名继续保持默认关闭，只在用户主动开启时发送。
一个会直接影响首字延迟的现有细节：AudioCapture.startCapturing() 会把预缓冲中所有完整的 200ms 块拼成一个 Data 返回，VoiceSession 再把它作为一条 WebSocket message 发出。默认 400ms 预缓冲因此可能形成一个 400ms 首音频包，超出火山官方建议的 100–200ms。托管客户端改造时应按原顺序拆回 100–200ms message；不要丢掉预缓冲，也不要在服务器端转码。
03 / Field research

公开项目已经验证“设备 → 自有服务 → 火山 ASR”可行

最有价值的服务端参照不是另一个 macOS 输入工具，而是 xiaozhi-esp32-server：它在服务器端接收设备音频、建立火山 WebSocket、缓存并补发音频、解析 definite 结果，再进入 LLM/TTS 管线。另一个小而直接的参考是 doubao-asr2-openai-proxy，它已经明确接入 Seed-ASR 2.0，说明早期“没有开源项目验证 2.0”的结论已经过时。

OpenLessRust SAUC 协议、错误处理与非输入法文本注入MIT仍偏客户端实现

WhisperLiveKit成熟的实时 WebSocket、并发用户、VAD、稳定前缀和 Deepgram 兼容协议Apache-2.0；约 10k★通常需要 GPU；中文、热词、标点和 definite 语义不会与 Seed-ASR 完全一致

火山还公开了测试阶段的 边缘大模型网关 Realtime API。其 transcription_session.update、input_audio_buffer.append/commit、completed 等事件适合作为第二阶段自有协议的命名参考；但文档对真正增量 delta 的支持有限，因此客户端协议应优先传“当前完整快照 + definite/final”，不要假设所有上游都能给 token 级增量。

调研结论：开源代码足以证明服务端流式转发可行，但没有哪个项目可以原封不动满足 Viva。最省风险的组合是：自研一个很薄的 Go SAUC 网关，首版 LLM 直接实现方舟轻量 Adapter；确有多 Provider 需求后再引入仅内网可见的 LiteLLM。用户、套餐和用量控制保持在你的业务服务内。
04 / Architecture options

三种架构的取舍

方案结果一致性首版开发量延迟供应商可替换性建议
A. 客户端继续直连火山，仅向服务器取临时凭证最高低最低低不建议 如果火山不提供安全的短期会话凭证，你仍会把可滥用凭证发给客户端
B. SAUC 二进制透明代理极高中低增加一段网络，但可压到很小中低首版推荐 最大程度复用现有实测协议
C. 自定义统一语音协议，服务器完全解析/生成 SAUC取决于实现高可优化最高第二阶段 适合多 ASR Provider 和服务器端 ASR→LLM 串联

为什么第一版不直接选择 C

当前 SaucProtocol.swift 已处理两条 sequence 路线、错误帧差异、gzip、防御性长度解析，以及官方表中未记录但 bigmodel_async 会出现的 asyncFinal = 0b0100。第一版同时重写这些协议细节，会把“服务端化”和“协议重构”两个高风险变量绑在一起，难以定位回归。

06 / Gateway protocol

第一版协议：二进制帧保持兼容，文本帧只承载网关控制消息

方向WebSocket message处理规则
客户端 → 网关第一条 binary：SAUC full client request只读解析和白名单校验；managed client 必须已使用伪 UID，默认按原字节转发；不接受上游 URL、resourceId 或密钥
客户端 → 网关后续 binary：SAUC audio only request每条 message 原样、串行转发；检查帧类型、字节速率、时长和末包
火山 → 网关 → 客户端binary：全部 SAUC response不改 sequence、flags、gzip、payload、close 时序
网关 → 客户端text：gateway.* JSON返回 trace_id、logid、额度、网关错误和重试建议；客户端不要交给 SAUC parser

07 / Zero-config auth

“用户不用填 API Key”不等于“客户端不需要身份”

桌面 App 里任何固定 secret 都能被逆向提取。正确做法是让首次安装自动生成设备密钥并领取小额试用身份；持续使用或付费后，再绑定账号/许可证。

  1. 设备生成密钥：首次启动生成 P-256 密钥对；私钥放 Keychain/Secure Enclave，服务器只保存 public JWK 与安装 ID 哈希。
  2. 自动 bootstrap：POST /v1/client/bootstrap 提交 App/设备信息、随机安装 ID 和 public JWK；Header 携带无 Access Token 的 Token Endpoint DPoP proof，proof JWK 必须与 body 中的设备 JWK 一致。
  3. 签发令牌：access token 10 分钟，仅驻内存；refresh token 30 天，放 Keychain 并滚动轮换。
  4. 匿名试用：按设备、IP 段、ASN、版本、并发和时长设小额度；异常时要求登录或验证码。
  5. 付费绑定：网站登录/支付后通过 Universal Link 或 viva://activate 回到 App，用户不复制任何 Key。
措施能防什么不能防什么
设备公钥签名简单复制 token、伪造设备请求攻击者完全控制一台真实设备后的自动化
短期 JWT + refresh rotation泄漏后的长期滥用、封禁传播慢在线窃取且即时使用
每设备/账号并发 1把一个账号当公共代理池大量注册新账号
按音频毫秒计量空闲挂连接、伪造客户端显示低速真人薅试用
服务端模型与 Prompt 白名单把润色接口滥用成通用聊天 API在允许文本内进行内容攻击；仍需内容安全策略
08 / Server implementation

推荐技术栈：Go 负责实时数据面，Postgres/Redis 负责控制面

组件推荐理由
实时网关Go 当前稳定版并锁定 toolchain，net/http + github.com/coder/websocket双 WebSocket I/O 成本低、Context/取消语义清晰；避免新项目继续采用已迁移的 nhooyr/websocket 路径
LLM 网关首版直接调用方舟；多模型后引入 LiteLLM（仅内网）避免过早引入重控制面，同时保留供应商回退能力
数据库PostgreSQL 16用户、设备、套餐、订单、使用记录与审计数据的事实来源
缓存/限流Valkey 8+ 或许可证明确的托管 Redis-compatible 服务并发租约、短时配额、refresh 撤销、幂等键；音频帧不经过缓存层
入口云负载均衡；单机阶段用 Nginx/CaddyTLS、WebSocket Upgrade、证书更新、限连接
密钥云 Secret Manager/KMS；MVP 可用权限 600 的独立 env 文件不写进镜像、Git、日志或数据库明文
观测Prometheus + Grafana + Loki/云日志 + OpenTelemetry必须拆分网关、上游和模型三段延迟

网关核心伪代码

func StreamASR(w http.ResponseWriter, r *http.Request) {
    claims := VerifyAccessTokenAndDPoP(r)        // 本地验签，不查数据库
    lease := AcquireConcurrencyAndQuota(claims) // 原子租约 + 额度预留
    defer lease.ReleaseOrSettle()

    client := UpgradeWebSocket(w, r)
    defer client.Close()

    // 关键：上游建连与读取/校验客户端首包并行，不能串行多等一个 RTT。
    upstreamCh := DialVolcAsync(VolcHeadersFromSecretManager())
    firstCh := ReadAndValidateFirstSAUCAsync(client, claims)
    upstream, first := AwaitBoth(upstreamCh, firstCh)
    defer upstream.Close()

    // managed client 已生成伪 UID；默认保持整条 SAUC message 字节不变。
    // 只有显式兼容旧客户端的版本化路径才允许受测 rewrite。
    upstream.WriteBinary(first.RawMessage)
    SendUpstreamReady(client, upstream.ResponseHeader("X-Tt-Logid"))

    // 每个方向只有一个 writer；有界队列；任一方向失败即取消另一方向。
    go PumpClientAudioToVolc(client, upstream, ByteRateLimit, SessionLimit)
    PumpVolcFramesToClient(upstream, client)

    // 会话结算进入持久 outbox/append-only ledger；不能只依赖内存 goroutine。
    PersistUsageCompletion(forwardedAudioMilliseconds)
}

关键并发规则

  • 每个方向只有一个写协程，严格保持首包 → 音频包 → 末包顺序。
  • 使用有界缓冲，例如每方向 8–16 个 message；满了就施加背压或结束会话，绝不无限吃内存。
  • 已建立会话中 access token 到期不强断；下一次建连前刷新。
  • 配额在连接前预留，音频时长按实际转发字节计算；结束后异步落库并对账。
  • 客户端断开时立即关闭上游，防止孤儿 WebSocket 继续计费。

Nginx WebSocket 要点

map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

location /v1/asr/ {
    proxy_pass http://viva_gateway;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    proxy_set_header X-Request-ID $request_id;
    proxy_buffering off;
    proxy_request_buffering off;
    proxy_read_timeout 120s;
    proxy_send_timeout 120s;
}

NGINX 官方说明 WebSocket 的 Upgrade 与 Connection 是 hop-by-hop header，反代时必须显式传递；默认 60 秒无数据会关闭连接，因此要提高 proxy_read_timeout 或发送 ping。

10 / Latency

最低延迟的关键不是“更快服务器”，而是把串行等待改成并行

优化预期价值注意事项
网关部署在中国大陆、优先北京做基线缩短网关 → 火山/方舟路径不要凭地理直觉定终局；用北京/上海/广州真实 A/B 数据选区
首版每次会话新建 WSS，但启用 DNS 缓存、TLS 1.3 会话恢复与控制 API keep-alive减少握手成本，同时保持“一条客户端 WS 对应一条火山 WS”的清晰边界跨会话长期复用同一 WSS 属于第二阶段自定义协议；不要在透明代理阶段偷偷引入
热键触发后并行：上游建连 + 本地采集握手时间被 200–400ms 音频缓冲覆盖现有 Viva 已先 startASRClient() 再取 pre-roll，应保留
把 400ms pre-roll 拆成 100–200ms message，主包维持 200ms符合官方建议，避免首个音频 message 过大拖慢首字只改变 WebSocket message 边界，不改变 PCM 字节、顺序或总时长；先做逐帧 A/B

11 / LLM pipeline

大模型接口应该是“产品能力”，不是“通用 OpenAI 代理”

客户端只提交原文、润色模式和用户主动授权的上下文；服务器固定 system prompt、模型白名单、关闭思考参数、最大 token 和安全护栏。这样一个被提取的用户 token 只能润色文本，不能被拿去跑任意聊天、代码生成或超长上下文。

推荐模型策略

  • 默认档：国内 mini/flash 非推理模型；温度 0–0.2；关闭 thinking；目标 1 秒内完成短句。
  • 质量档：仅对长文本或用户主动选择时使用 lite/pro，设置更严格的超时和额度。
  • 故障回退：主模型 429/5xx 时回退第二家国内模型；不得因回退把数据跨境发送，除非用户明确同意。
  • Prompt 版本化：服务器记录 prompt_version，可灰度和回滚；客户端不上传任意 system prompt。
  • 双重护栏：服务器做长度/语言/相似度检查，客户端继续保留现有 isSaneResult()。
未来 v2 的延迟最优目标态：服务器接到火山 final 后立即调用方舟，客户端不再单独发起润色 HTTP 请求。该能力必须先新增 /v2/realtime 协议和机器契约；当前 v1 仍由客户端在收到 final 后调用 /v1/text/polish/stream，失败则使用原文。
12 / Security & privacy

默认不落音频、不记全文，密钥和计量都在服务端完成

风险控制措施
火山/LLM Key 泄漏Secret Manager/KMS；最小权限；多环境分离；日志全量脱敏；定期轮换
客户端 token 被提取短期 JWT、设备公钥签名、并发 1、额度、异常速率封禁、refresh rotation
音频/文本泄露TLS；内存流转；默认不持久化；错误日志只存长度、哈希、trace 与供应商 logid
Prompt 注入/接口滥用产品专用 schema；服务端 system prompt；模型/长度/token 白名单；输出相似度护栏
重放与重复扣费DPoP jti 重放缓存、request_id + Idempotency-Key、服务端 usage ledger
孤儿连接继续计费客户端断开即取消上游 context；双向 pump 共享 cancel；会话最大时长
服务商故障明确错误、指数退避、熔断；LLM 可回退，ASR 首版不做静默跨厂商切换
集中托管/转供授权不明确公开 Beta 和收费前取得火山关于面向终端用户集中托管、计费归属、并发扩容和企业容量的书面确认；不能仅凭技术上可调用就假定合同允许

面向中国大陆用户的合规清单

  • 隐私政策明确说明：音频先到你的服务器，再转发火山；开启润色后，识别文本还会进入所选模型服务。
  • 说明处理目的、数据类型、保存时长、第三方处理者、删除路径、客服渠道和账户注销方式。
  • 默认使用境内模型与境内部署；如果提供海外模型，单独提示跨境风险并取得明确选择。
  • 不要默认记录音频或完整文本；调试采样必须显式开启、限时、可见并可删除。
  • 面向公众提供生成式 AI 功能、收费互联网服务、域名和 App 分发可能涉及额外备案/许可义务，应在正式商用前由专业法律顾问确认。

本节是工程合规检查表，不构成法律意见。核心参考包括《中华人民共和国个人信息保护法》和《生成式人工智能服务管理暂行办法》。

成本公式与解释
  • 语音小时 = 月活 × 每天分钟 × 活跃天数 ÷ 60。
  • PCM 流量 = 小时 × 码率(kbps) × 3600 ÷ 8 ÷ 1,000,000；这里只计算网关向火山的公网出站，实际云厂商规则可能不同。
  • 峰值并发 = 日语音小时 ÷ 集中使用时段 × 峰值系数，向上取整。
  • LLM = 润色次数 ×（输入 token × 输入价 + 输出 token × 输出价）÷ 1,000,000。
  • 未包含支付通道、税费、客服、退款、风控损失和营销成本。

17 / Roadmap

建议 6–10 周完成可收费版本

编号说明：这里的 P0–P5 是产品排期视图，不替代交接包中的工程 M0–M7。编码 AI 必须按 M0→M7 顺序验收；P1 只有在 M1 Fake Upstream 协议 PoC 和 M2 认证完成后，才能进入 M3 真实火山联调。

Keychain、bootstrap/refresh、ManagedGatewayClient、欢迎页零 Key 流程、BYOK 回退。

WEEK 4–5

Postgres ledger、Redis 并发租约、管理页、Prometheus/Grafana、告警、用量对账。

WEEK 5–7

18 / Risks

最容易低估的六个风险

风险概率/影响对策
默认 50 并发仍可能在集中办公时段触顶中高 / 高按活跃时段和峰值系数建模；Beta 前接入并发拒绝指标；提前申请扩容
匿名试用被逆向批量盗刷高 / 高额度小、设备签名、IP/ASN 风控、并发 1、异常版本封禁；付费必须绑定账户
中转网络比直连差中 / 高北京/上海/广州 A/B；连接复用；分段 trace；保留直连回退
代理改坏未公开协议细节中 / 高首版透明转发、黄金帧测试、原样保留 asyncFinal 和 close 时序
“隐私工具”变成中心化数据处理者高 / 高不落音频/全文、明确披露、国内默认、删除与注销、内部最小权限
订阅价覆盖不了重度用户中 / 高额度套餐而非无限量；超额包；按真实分钟数持续校准
Go / No-Go 门槛：只有当代理对同一测试集的最终文本无系统性退化、中转新增 p95 ≤ 50ms、p99 ≤ 100ms、会话成功率 ≥ 99.9%、孤儿计费为 0、匿名试用滥用率可控，并已取得火山对集中托管/转供和目标并发容量的书面确认时，才把托管模式设为全量默认。
